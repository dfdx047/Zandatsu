## 4. Pulos na tela em ultrawide

- Causa: o Renut decide por frame se o frame é "2D" (logos, vídeos: mostra 1280 colunas como 16:9) quando tem menos de
  8 draws alargados. A conta era feita no Swap da thread do jogo, mas os draws eram contados na thread de render, e
  viewports reaproveitados não contavam. Frames de jogo caíam no 2D e piscavam em 16:9.
- Correção (`renut/0039`): conta por draw depois do bloco do viewport (`draw.cpp`) e decide dentro do QueueFrame da thread
  de render; só passa a 2D depois de 3 frames seguidos. Log `[renut] widescreen: ...` (até 40 linhas).
- Verificado: as únicas trocas são nas logos do arranque e numa tela de loading (3 draws). Nenhuma na luta.

## 5. Céu preto na Mali-G615

- Reproduzido na luta do prólogo: céu preto (o resto da cena certo).
- Descartado com cvars: passe de scissor, lista própria de present, BC na CPU, sem depth clip, depth sempre, sem
  stencil, sem culling. A textura do céu (`F9258188`, 4096x1024 DXT1) aparece certa com `banjo_renut_diag_show_texture`.
- Dump do frame: o draw do céu (VS `7CB833987A90E040`, PS `B05573FCC2970ABD`) tem `fogParam` (VS c184) = **(+inf, 60000, 0, 0)**.
  O VS calcula `fog = saturate(fogParam.x * (fogParam.y + viewZ))`. A Xenos multiplica como o D3D9 (`0 × inf = 0`); no
  host dá NaN quando o termo é 0, e o `saturate(NaN)` é indefinido: a Mali devolve o nevoeiro, preto (no Adreno o céu já saía certo).
- Correção (`renut/0041`, cvar `swordman_renut_finite_constants`, ligada): ±inf nas constantes float vira ±FLT_MAX ao
  subir para a GPU. Só muda o resultado nesse caso. Deve resolver a mesma coisa noutras Mali (céus/nevoeiro pretos).
- Verificado no debug e no release final: céu com nuvens e fumo. O minimapa como quadrado amarelo cheio (#36) continua.

## 6. Desempenho (1080p a 60)

Luta do prólogo, 45 s, mediana das janelas de 10 s. Telefone na tomada e quente durante todo o teste (estado térmico 3,
`devfreq-13000000.mali` com limite 40, pele 44–55 °C). Clock da GPU pelo perfetto (`power/gpu_frequency`).

| Configuração | fps | GPU ms | Clock da GPU |
|---|---|---|---|
| 720p 16:9 | 54,4 | 12,6 | |
| 720p ultrawide | 29,8 | 24,5 | |
| 720p ultrawide sem sombras | 52,1 | 13,1 | |
| 540p ultrawide | 52,9 | 12,0 | |
| **1080p 16:9** (Alto) | **46,1** | 18,4 | 601 MHz 73% do tempo |
| 1080p ultrawide (Alto), vsync | 29,8 | 26,9 | 344–483 MHz |
| 1080p ultrawide, vsync desligado (FIFO, antes) | 29,9 | | |
| 1080p ultrawide, vsync desligado (MAILBOX, `renut/0040`) | 34,3 / 29,8 (2ª, mais quente) | 27,0 / 28,0 | 403–502 MHz |
| 1080p ultrawide, ADPF sem tempo de GPU | 35,3 | 25,0 | |
| 1080p ultrawide, interpolação 120 | 29,6 | 28,6 | |

- O ultrawide desenha ~70% mais (1268 draws/frame contra 738; só profundidade 668 contra 304): o FOV mais largo mete
  mais cena.
- O jogo está limitado pela GPU (thread do jogo 33,7 ms de Swap a Swap, 0 ms à espera). A Mali-G615 vai até ~1,4 GHz,
  mas quente fica em ~600 MHz; em ultrawide o governador da MediaTek (FPSGO) trava ainda mais baixo (~400–500 MHz)
  quando o jogo cai para 30.
- **1080p a 60 não dá neste aparelho nestas condições.** O melhor: 1080p 16:9 a 46 fps, ou 720p 16:9 a 54 fps.
  Não medi com o telefone frio e fora da tomada; é a medição que falta para saber o teto real.
- MAILBOX: com vsync desligado o Android só tinha FIFO (sem IMMEDIATE) e os frames arredondavam para 30. Agora usa
  MAILBOX: +4,4 fps na 1ª corrida; na 2ª, já com 50 °C, igual.
- Sugestão do perfil para a Mali-G615 fica em **Médio** (não mudei).
